# Todoist triage

Todoist is the real task store. The vault holds almost no tasks and the daily notes hold none.

## The protocol he has stated

1. **Survey first.** Read the existing project and label structure before proposing anything.
   Match what is already there rather than inventing a taxonomy.
2. **Propose one item, then stop.** Not a batch. Wait for a yes before the next one.
3. Apply only what he approved.

His words: "Do not add anything until I approve. Propose each task one at a time." and
"First, show me the tasks and don't write anything."

## Conventions

- Projects are two-level: `Parent → Child`. Put the task in an existing child where one fits.
- Priorities are P1 to P5.
- **A description is mandatory.** His test: "I can understand what needs to be done by looking
  at the task alone." No task that only makes sense next to its source.
- Task text is self-contained. Expand into subtasks where the work has real steps.
- Due dates: check the calendar and existing load, then place it on **a Sunday from a lighter
  week**. Untimed Sunday tasks are the weekly-planning pool, so only give a time or a near
  date when the work genuinely needs one.
- Include as much context in the description as you have.

## Guardrails

- Never complete, delete or reschedule an existing task without being asked for that task.
- When a source note exists in the vault, link it rather than copying its text.
- If an item is ambiguous, ask with at least two concrete options.
